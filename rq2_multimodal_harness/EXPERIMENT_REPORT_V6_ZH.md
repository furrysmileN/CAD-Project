```mermaid
flowchart LR
    A["本地点云程序<br/>量出结构化几何证据"] --> B["通义千问 qwen3.8-max<br/>看 T0 / 四视图 / 证据 JSON<br/>写出 Plan"]
    B --> C["HarnessCAD C 臂<br/>R4 + 最多 2 轮回修<br/>keep_best=false"]
    C --> D["几何分 + 关键 feature 分"]
    D --> E["本报告"]
```

**现阶段允许说**

- 弱文本下，图像与**整包** point-cloud-derived structured geometric evidence 仍有双向边际增益。
- 模型能读到序列化后的关键事实（readback）。
- 口袋深度：图像分不清两种深度时，把点云证据换成配对零件 B，Plan 里的口袋深度会跟着变成 B。

**现阶段不允许说**

- 已经证明互补来自各自独有的 CAD 事实（H2/H3 未在有效仪器上确认）。
- 通/盲或背面特征会被反事实证据改写。
- 已经用 Holm 校正对外宣称 V6 显著性。
- 通义千问直接消费了原生点云 token / embedding。

## 1. 我们在研究什么问题

### 1.1 V5 已经解决了什么

V5 在**新的 100 零件**、3 次重复、Holm 校正下支持：

- 照片 + 完整几何说明，同时优于纯照片（约 +0.26）和纯几何说明（约 +0.06）；
- 旧剪影、张冠李戴的错配说明都更差。

那是「模态有没有」的问题。它**不能**回答：模型用的是图像缺失的那条 CAD 事实，还是更长的输入、重复表达、结构化模板？

### 1.2 V6 原先要回答的问题

自变量从「给哪种模态」改成「每种模态携带哪些 CAD 事实」。六个条件都带同一句弱文本 T0（不含尺寸、孔数、深度、family 名）：

| 对模型 ID | 输入 | 本意 |
|---|---|---|
| C0 | T0 | 基线 |
| C1 | T0 + 四视图 | 只有图像 |
| C2 | T0 + `P_comp` | 只有点云派生证据 |
| C3 | T0 + 四视图 + `P_comp` | 图像 + 完整证据 |
| C4 | T0 + 四视图 + `P_repeat` | 删掉关键事实，用可见面冗余测量补长度 |
| C5 | T0 + 四视图 + `P_wrong` | 只改一个预注册字段 |

预注册假设：

```text
H1a  C3 > C1     点云证据叠在图像上有增益
H1b  C3 > C2     图像叠在点云证据上有增益
H2   C3 > C4     独有事实优于重复事实
H3   C3 > C5     正确事实优于局部错误事实
H4   关键 feature 与预注册缺口同向
K6   C3 − C1 − C2 + C0   协同项，单独报告，不替代 H1
```

主几何指标：`first_attempt` 的 failure-aware `joint_quality`（越大越好）。`keep_best=false`。点云对外只允许说 **point-cloud-derived structured geometric evidence**。

### 1.3 实际发生了什么：诊断轮冻结，改走 V6b

20×6 live 跑完后，H1 方向清楚，H2/H3 的对照字段大多没构成可用操纵。2026-08-26 决定：

- 这 20×6 **冻结为仪器失效诊断轮**，不进正式推断；
- **暂停** 100×6×3 confirm；
- 不再用 1800 任务重复确认 H1；K6<0 不修；
- 因果问题改写为 V6b：

> 当图像无法区分两个 CAD 反事实，而点云证据只在一个关键事实处发生**自洽**变化时，生成的 CAD 是否随该事实变化？

C5 不再手工改 JSON 里一个字段，改为配对零件 B 的真实点云经同一 PointEvidence 生成器得到的 `P_B`。

## 4. 第一层核对：为什么 C3≈C4≈C5 不能写成「模型不用点云」

工程审计（有没有 `primary_critical`、P_repeat 是否删掉该 `fact_id`、P_wrong 是否只改这一条）**20/20 通过**。那只保证改了 JSON 标记，不保证改到了模型可能使用、且等于 GT 缺口的测量。

科学审计：

1. **关键事实测准率 5/20。** 法兰间距 4/4 为 `null`；口袋深度 4/4 被标成 bbox 最长边 `1.0`；背面特征 4/4 测成 `false`（GT 为 `true`）。对这些样本做 C4/C5，改的不是 GT 缺口。
2. **轴线负对照有碰撞。** 0017 的 `P_wrong` 随机替换撞回 `[0,0,1]`，C5 作废。
3. **真正合格的 K3/K4 对照只有 4 例。** 这 4 例上 C5 的关键预测**全部仍等于 C3**。
4. C3 与 C4 的 `joint_quality` 有 10/20 完全相同；C3 与 C5 的 feature 预测 19/20 相同。

因此 C3≈C4≈C5 **首先应解释为对照失效**。K1/K2 已经表明模型在使用**整包**点云证据和图像；它没有使用的是被标记为 `primary_critical` 的那一个字段。

这 20 个样本**不得**再筛进后续 confirm。

明细：`outputs/v6_information_complementarity/pilot/live/analysis/layer1_audit.json`。冻结说明：`PILOT_FROZEN_AS_INSTRUMENT_DIAGNOSTIC_ZH.md`。

## 5. V6b：把四层拆开

```text
点云是否测准
  → 模型是否读到
    → 模型是否写进 Plan
      → Harness / 评分是否检测到
```

### 5.1 离线仪器（无 API）

## 6. V6b 小探针：写入层只在口袋深度上干净成立

主看 `first_attempt` 的 **critical-feature**。主指标是 **严格跟随**：C3 的预测值与 C5 不同，且 C5 落到 B。  
**不要把「C5==B」单独当成 H3b**——若 B 恰好是模型默认值（无背面孔、通孔），C5==B 会被默认值撞上。

两轮都是 11 对 × 6 条件 × 2 重复 = **132/132 completed**。n=11×2，**不得做显著性宣称**。

### 6.1 两轮对照

| 项 | 第一轮（默认值膨胀） | 仪器修复后 |
|---|---|---|
| 评分 | `rq2.v6.feature.v2` | `rq2.v6.feature.v3`（通孔深度不再冒充盲孔/口袋） |
| 通/盲与背面的 B | 常为默认值 | B 改为非默认（blind / 有孔） |
| C3 与 C5 Plan 哈希相同 | 0/22 | 0/22 |
| C5==B | 20/22 | **8/22** |
| **严格跟随** | 9/22（41%） | **8/22（36%）** |
| C3 预测值 = A | 5/22 | 15/22 |
| `joint_quality` C3 / C4 / C5 | 0.89 / 0.88 / 0.90 | 0.88 / 0.88 / 0.90 |

修复后 C5==B 与严格跟随相等：默认值膨胀已去掉。`joint_quality` 仍然分不开 C3/C4/C5。

### 6.2 按事实类的严格跟随（以修复后为准）

| 类 | n | 严格跟随 | 说明 |
|---|---:|---:|---|
| 口袋深度 | 6 | **6/6** | C3 常接近 A（~0.13）或评分为空；C5 拉到 B（~0.26） |
| 盲孔深度 | 4 | 2/4 | 0008 写出 0.30；0000 仍写两个通孔，v3 评分为 `None`（不再误读成 0.42） |
| 通/盲 | 6 | **0/6** | C3/C5 都写 through；证据要求 blind 时没有改浅 |
| 背面有无 | 6 | **0/6** | C3/C5 都不写背面孔；证据要求有孔时没有加上 |

抽查与评分一致：0000 的 C5 Plan 是两个 `depth=0.42` 的孔；0001 的 C5 在证据要求盲孔时仍写 `through_hole`。

### 6.3 探针 Go 门槛

| 门槛 | 修复后 |
|---|---|
| C3/C4/C5 不再大面积同一份 Plan | 通过（三份全同 0/22；C3 与 C5 哈希相同 0/22） |
| 整体严格跟随 ≥50% | **未过**（8/22） |
| 按类都过 | **未过**（仅口袋 6/6） |

**不要开 1800 confirm。** 也不要为了让跟随变好看去改 CAD Prompt。

## 7. 四层现在分别停在哪

| 层 | 状态 | 依据 |
|---|---|---|
| 测量 | 最小对上可用（11/12 合格）；confirm100 为 92/100 | 离线审计 |
| 读回 | 通过 | readback 11/11 |
| 写入 Plan | **仅口袋深度稳定**；通/盲与背面未跟随 | 修复后探针 8/22 |
| 评分检测 | Oracle 100/100；v3 不再把通孔当盲孔 | confirm100 + 0000 抽查 |

因此当前最硬的机制结论不是「模型完全不用点云」，而是：

> 它会使用整包证据把总体形状做对；在图像分不清、必须改写一个非默认 CAD 事实时，只有口袋深度被稳定写进 Plan。

## 8. 局限与明确不做

- 全部 V6 live 都是描述性的：pilot n=20、探针 n=11×2，没有正式推断。
- 探针四类样本量不均（口袋/通盲/背面各 6 次重复对，盲孔只有 4）。
- 图像泄漏：通/盲顶视 L1 最大约 0.006，不是严格像素恒等；设计目标是「四视图无法分辨 \(f\)」。
- `v6b_probe_0004` 因测量失败未进推断。
- 未做：工具调用、候选 CAD 反馈、`P_enc`、换模型、扩展 DSL、从 diagnostic 20 筛 confirm、为抬指标改 Prompt。
- 不能外推到自然零件上的「任意关键特征」；口袋深度的阳性不能自动推广到盲孔或背面孔。
